## Markdown alternate links that resolve

Every bundled theme built the `<link rel="alternate" type="text/markdown">` href by appending `.md` to the page URL. That produced dead links such as `/.md` on the homepage, `/posts/.md` on collection indexes (the file is `/posts/index.md`), and links to markdown that is never written on tag pages, paginated pages, and the 404 page.

Templates now get `page.markdown_url`, the path of the markdown copy the build actually writes: `/posts/hello-world.md` for a post, `/posts/index.md` for a collection index, and `/index.md` for the homepage when `content/pages/index.md` exists. It is unset when no markdown copy is written for the page, and all 10 themes only emit the link when it is set:

```html
{% if page.markdown_url %}<link rel="alternate" type="text/markdown" title="Markdown" href="{{ site.base_url }}{{ page.markdown_url }}">{% endif %}
```

Existing sites keep their copy of `templates/base.html`, so run `seite theme apply <name>` to pick up the fix, or replace the old markdown link in a custom `base.html` with the line above.

## robots.txt: Anthropic crawlers and Content Signals

The generated `robots.txt` keeps the same policy (allow AI search and user-initiated fetches, block AI training) and covers more crawlers. `Claude-SearchBot`, `Claude-User`, and `Perplexity-User` are now allowed. `ClaudeBot`, `Applebot-Extended`, and `meta-externalagent` are now blocked. The `User-agent: *` group also carries a [Content Signals](https://contentsignals.org) line, `Content-Signal: search=yes, ai-input=yes, ai-train=no`.

## Markdown for readers' agents

- **Every `.md` copy points to the site index.** Right after its frontmatter, each published markdown copy (pages, collection `index.md`, homepage `index.md`) now starts with one line: `> Index of this site for agents: [llms.txt](…). Full text: [llms-full.txt](…). All pages: [sitemap.md](…).` with absolute URLs (pages in another language link that language's `/<lang>/llms.txt`). Existing sites see this line appear in their `.md` files on the next build. `llms-full.txt` is unchanged.
- **`/sitemap.md`**: every page's markdown URL with its title and description, one section per collection (and language), from the same pages as `sitemap.xml` minus `noindex` pages and drafts. `llms.txt` links it in one new line under its header.
- **`Accept: text/markdown`.** `seite serve` answers a page request whose `Accept` header prefers `text/markdown` over `text/html` with the page's markdown copy, and marks negotiable HTML with `Vary: Accept`; browsers and `*/*` still get HTML. `.md` URLs are now served as `text/markdown; charset=utf-8` (was `text/plain`).
- **Cloudflare Pages.** The password-access Worker (`[access]`) does the same negotiation, after its password check. Sites without `[access]` can opt in with `[deploy] markdown_negotiation = true`, which generates a small `_worker.js` and `_routes.json` (static assets, social cards and the search index skip the Worker). It is off by default because every page request then counts as a Functions request (Workers Free: 100,000 a day); `seite build` warns when it is set for another deploy target. Netlify and GitHub Pages get no negotiation; [Deployment](/docs/deployment#markdown-for-agents) explains why and has a manual Netlify Edge Function example.

## Theme contrast fixes

- **default**: hovering the skip-to-content link turned its text dark blue on the blue background. It now stays white. Headings also have explicit sizes, so `h1`, `h2`, and `h3` are clearly distinct.
- **dark**, **landing**, **magazine**, **brutalist**: the same skip-link hover problem. In brutalist the text became yellow on yellow.
- **minimal**, **academic**, **bento**, **landing**, **dark**: muted text (dates, search result meta, footers, breadcrumbs) was darkened or lightened to meet the WCAG AA 4.5:1 contrast ratio.

### Agent-facing CLI

- `seite context`: once-per-session orientation for coding agents (site, collections with counts, theme, local docs, skill packs, agents and hooks, running dev server) ending in `NAME: message` directives (`UPGRADE_AVAILABLE`, `NO_STOP_HOOK`, `ADDON_SUGGESTION`). Works outside a project.
- `seite docs [query] [--topic slug]`, `seite page <path|url>`, `seite search <query>`, `seite stats`, `seite templates` and `seite frontmatter set|unset`: every MCP-only capability is now a CLI command with `--json`, running the same code as the MCP tool.
- `seite explain <code>` and a new [error reference](/docs/errors) with one section per diagnostic code. JSON diagnostics gain a `docs_url` field, and `seite check` ends with a pointer to `seite explain` when it reports problems.
- New `template-markdown-link` warning: `seite check` and `seite build` point at custom templates that still build `{{ page.url }}.md` links, with the `page.markdown_url` replacement as the hint.
- `seite check --file` reports each path it skipped (missing, outside the site, not a content/template/data file) as a `check-file-skipped` warning instead of passing silently; `--strict` fails on them.
- `seite serve` records the running server in `.seite/dev.json` (removed on stop, Ctrl-C, or SIGTERM), so `seite context` can report it; a second `seite serve` in the same directory prints the running URL and exits unless `--force-new` is passed.
- Run at a workspace root without `--site`, `seite context`, `page`, `search`, `stats`, `templates`, and `frontmatter` say "this is a workspace: pass --site <name>" and list the sites.
- `seite upgrade --agent [--with <agent>]` upgrades, then builds a migration brief from the release notes since the project's recorded version (all entries, capped at about 48 KB, when the version is unknown): what changed automatically, the notes, and instructions to apply manual steps and run `seite check` and `seite build` until clean. Inside an agent session (or with `--json`, or without a terminal) it prints the brief (`data.brief`); from a terminal it saves the brief to `.seite/upgrade-brief.md` (gitignored) and starts the chosen agent with a one-line prompt to read it, never with auto-approve flags. Cannot be combined with `--check`. The `/seite upgrade` skill now uses it.
- `.seite/docs/` is gitignored and written lazily: `seite context` and `seite docs` write it when it is missing or from another seite version, and pages a version no longer ships are pruned.
- `seite skill install|update|remove impeccable` installs the impeccable design skill for the project's agents through its npm installer (pinned version, fetched into a temp directory so project npm config can't swap it, then `impeccable install --providers=<agents> --scope=project` in the site), after asking; `seite skill list` shows it.

### Agent setup

- **Gemini CLI** is a supported agent (`--agents gemini`): `GEMINI.md` imports `AGENTS.md`, `.gemini/settings.json` carries the hooks, and `/seite` is a `.gemini/commands/seite.toml` command. `seite agent --with gemini` launches it.
- **One routed `/seite` skill.** `SKILL.md` is short and points to one `reference/<command>.md` per command: check, new, preview, build, deploy, theme, brand, landing, collection, upgrade, hooks. `theme-builder`, `brand-identity`, `landing-page`, and the `design-prompts` rule are folded into `/seite theme`, `/seite brand`, and `/seite landing`. Verification is bounded: check, fix everything, check once more, stop.
- **Compact AGENTS.md** (about 3.5 KB): what the site is, layout, collections, content format, hard rules, and the workflow (`seite context`, then `/seite`). The command list, REPL docs, MCP tool list, and docs links are gone. The docs for the installed version are written to `.seite/docs/`.
- **Two-tier check hooks.** After each edit, `seite check --hook <agent> --post-edit` checks only the edited file; at the end of a turn, the full check runs. Hook commands exit 0 silently when `seite` isn't installed. `seite hooks on|off|status` manages them, and `seite check --file <path>` runs the fast per-file check by hand.
- **MCP is opt-in for coding agents.** `seite init` and `seite upgrade` only wire the MCP server in with `--mcp`; existing MCP config is left untouched. `seite mcp --dir /path/to/site` is documented for Claude Desktop. The `seite://mcp-config` resource is removed.
- **`seite agent` is a thin launcher**: the prompt is passed as-is (`claude "<prompt>"`, `claude -p` with `--once`), with no injected context, tool allowlist, or MCP flags. **`seite theme create`** runs `/seite theme <description>`, or points to `/impeccable` when it is installed.
- **Claude desktop preview**: `.claude/launch.json` declares the `seite` dev server for the desktop app's preview pane.
- `seite upgrade` removes the old skills and rule only when they are unmodified (content hash) and keeps edited copies with a notice.
- `seite hooks on|off --tier stop|post-edit|all` manages the two hook tiers separately. `hooks_installed` records each tier (`claude`, `claude:post-edit`), so `seite upgrade` no longer brings back a deleted after-edit hook. `seite hooks off` removes only hook entries whose command seite generated, and deletes OpenCode's plugin only while it is unedited.
- `seite upgrade` removes the `AGENTS.md` sections 0.20 wrote for the retired skills and the serve REPL when they are unedited (replaced by a one-line `/seite theme|brand|landing` pointer). The "Kept …" notices for edited legacy files print once, and never under `--check`.
- The Cursor hook always gets a JSON document on stdout, including when Cursor runs Claude Code's hooks and on internal errors.

### Security

- `--yes` / `SEITE_YES` no longer add the harnesses' auto-approve flags to `seite agent` or `seite theme create`. `seite agent --once --auto-approve` is the explicit opt-in, honored only from an interactive terminal outside an agent session.
- `seite agent` and `seite theme create` refuse to start a nested agent from inside a coding agent's session (Claude Code, Codex, Cursor, Gemini CLI, OpenCode), pointing to `/seite theme …` in the current session instead.
- Generated permissions allow only `seite theme apply` and `seite theme list` (not `theme create` or `seite agent`): Claude `Bash(seite theme apply:*)`, Cursor `Shell(seite:<subcommand>*)` per allowed subcommand instead of `Shell(seite)`, OpenCode `"seite theme apply*"`. `seite upgrade` narrows the 0.20 rules when they are still exactly as seite wrote them.
- `seite init`, `upgrade`, `hooks`, `skill remove`, and the dev server refuse to write or delete through a symlink inside the project (any path component), and check that the resolved parent stays inside the project.
- A planted `.seite/dev.json` can't spoof the dev server: its URL is ignored (rebuilt from the port), the port must accept loopback connections and the pid be alive, symlinked files are ignored, and new sites gitignore it.

### Content model

- **Taxonomies.** `[[taxonomies]]` in `seite.toml` adds term groupings beyond tags, such as categories: `name`, `label`, `url_prefix` (default `/<name>`), `feed` (default on), `paginate`, and `template`/`term_template` overrides. Pages assign terms with a top-level frontmatter key of the same name (`categories: [Rust, Web]`). Each taxonomy gets a term index (`/categories/`), a page per term (`/categories/rust/`, paginated when `paginate` is set), per-term RSS and Atom feeds (`/categories/rust/feed.xml`, `atom.xml`, linked from the term page), per-language versions (`/es/categories/...`), and sitemap entries. New embedded templates: `taxonomy.html` and `term.html`.
- **Tags are unchanged** unless configured: `/tags/` and `/tags/<slug>/` render exactly as before, without feeds. `[[taxonomies]] name = "tags"` opts tags into per-tag feeds and pagination.
- **Related pages.** `page.related` lists up to 3 pages from the same collection and language that share tags or other terms (a shared category counts twice as much as a shared tag; ties go to the closest date). `[build] related = N` changes the size, and `related = 0` (site-wide or on a collection) turns it off.
- **Series.** `series: "Rust from scratch"` (plus optional `series_order`) puts pages in a series: `page.series` has the ordered parts, the page's position, and the previous and next part, and each series gets an index page at `/series/<slug>/`. Nothing is generated when no page uses `series`.
- The default `post.html` shows categories next to the tags, a "Part 2 of 5" series box, and a "Related" list, all styled by every bundled theme. Tag links on post pages follow the tags taxonomy's `url_prefix`. `seite upgrade` replaces a site's `templates/post.html` with the new default when it is exactly a default an older `seite init` wrote; an edited copy is kept, with a one-time notice pointing at the snippet in [Templates](/docs/templates). New UI strings: `t.categories`, `t.related`, `t.series`, `t.series_part`.
- `seite search` / `seite_search` results include each page's `taxonomies` and `series`; `seite stats` / `seite_content_stats` report term counts per taxonomy and the series in use; `seite templates` / `seite_list_templates` describe the new template variables.
- Published `.md` copies of pages include the configured taxonomy keys (such as `categories`); other unknown frontmatter keys stay out of them, as before.
- `series:` is lenient: a list (Hugo style, `series: ["Rust intro"]`) uses its first entry, and `series_order` accepts numeric strings (`"2"`). Other shapes are ignored rather than failing the page.
- Per-term feeds have their own identity: the Atom `<id>`, the Atom alternate link and the RSS channel `<link>` are the term page's URL.
- Related pages stay fast on large sites: computed in parallel, only the top entries are ordered, and in a group of more than 200 pages a term carried by more than 20% of them (a `blog` tag on every post) no longer relates pages by itself (it still adds to the score of pages related by another term).
- `seite serve`: changing one part of a series re-renders the other parts, also in other collections.
- New diagnostics: `taxonomy-url-collision` (error: a taxonomy URL prefix already used by a collection, another taxonomy, `/series`, or a language, which would overwrite pages), `taxonomy-reserved-name` (warning: a taxonomy named after a built-in frontmatter field such as `extra`), and `series-url-collision` (warning: a series index page replaces a content page).
- **magazine** theme: tag links are 0.7rem instead of 0.68rem, so they no longer fall under the 11px legibility floor (applies when the theme is applied).
- **Typed frontmatter schemas.** `[collections.fields.<name>]` in `seite.toml` declares a field's `type` (string, text, number, integer, bool, date, datetime, url, image, enum, list, object), `required`, `enum`, `items`, `min`/`max`, `pattern`, `default`, and `description`. `seite build`, `seite check`, `seite check --file` and the after-edit hook report each violation as a `frontmatter-schema` error at the exact line, naming the field, what was expected and what was found, with the field's description as the hint. `strict_fields = true` adds `frontmatter-schema-unknown` warnings for undeclared keys. Built-in keys and `[[taxonomies]]` names validate at the top level; custom fields may be written at the top level or under `extra:` (validated wherever they appear; both at once is an error) and templates read either as `page.extra.<name>`; published `.md` copies include declared custom fields, never undeclared keys. `seite new` writes defaults and empty placeholders for required fields; MCP `seite_create_content` and `seite_update_frontmatter` refuse values that break the schema (and store new custom fields under `extra:`; existing ones are edited in place). `seite templates`, `seite context` and `seite_list_templates` include each collection's schema. New sites get small preset schemas (types and descriptions only: nothing required, no length bounds; numbers in `tags` still count as strings); `seite upgrade` adds none.
- **Scheduled publishing** (opt-in: `[build] schedule = true`, which `seite init` writes for new sites; existing sites build exactly as before, and `seite upgrade` only shows a one-time notice). In dated collections, posts with a future `date` are left out of every output (HTML, markdown, feeds, sitemap, search index, llms files, tag pages) until their date; `expires:` takes a post down after its date. `seite build --future`, `[build] future = true` and `seite serve` include scheduled posts. "Today" follows the new `[site] timezone` (IANA name or fixed offset), else the machine's local date — the same clock `seite new`/`init`/MCP create use to date new posts. `seite build`/`serve`/`check` print "N scheduled posts hidden; next goes live <date> (<title>)". `seite check` resolves links like the build — links from published pages to hidden posts are `link-to-scheduled` warnings with the go-live date (`--future` to preview) — and still validates scheduled posts. `seite stats` adds expired posts and the next scheduled one, `seite context` prints it, and the generated GitHub Actions workflows rebuild daily (`cron: '17 5 * * *'`); with `schedule = true`, `seite upgrade` adds the cron to unedited workflows and explains how to add it otherwise.
- **External link check.** `seite check --external` checks every external link in the rendered site (8 at a time, 2 per host, 10 s timeout, HEAD then GET, up to 5 redirects), caches working links for 7 days in `.seite/cache/links.json` (gitignored), skips hosts that block bots plus `[check] external_skip`, and reports `external-link-broken` / `external-link-unreachable` warnings (errors with `--strict`) at the source file and line.

### Themes

- **seite owns the SEO head; themes own layout and CSS.** Five embedded partials under the reserved `seite/` namespace carry what every theme duplicated: `seite/head.html` (description, canonical, Open Graph and Twitter tags, JSON-LD, hreflang, RSS/Atom/`llms.txt` and markdown links, robots, KaTeX), `seite/search.html` and `seite/search-script.html`, `seite/lang-switcher.html`, and `seite/scripts.html`. Every bundled theme includes them, so SEO, GEO and search fixes ship with the binary instead of needing `seite theme apply`. Rendered pages are unchanged, except: `landing` and `terminal` use the DOM-based search script the other themes use (result titles are no longer inserted as HTML, and terminal's result meta separator is `·`), `docs`' language switcher is a `<nav>`, and `landing`, `terminal`, `magazine` and `academic` now load the KaTeX stylesheet when `math` is on. A file at `templates/seite/<name>.html` overrides a partial (and stops receiving its fixes).
- **Starters and a gallery.** `seite init` offers four starters: `default`, `docs`, `landing`, and the new `blank` (`--theme`; a docs-only site gets `docs`). `minimal`, `dark`, `brutalist`, `bento`, `terminal`, `magazine` and `academic` are a gallery of examples, still embedded in the binary (offline, versioned with seite) and applied with `seite theme apply <name>`. `seite theme list` shows both groups.
- **Design your own theme.** `blank` is a bare semantic layout (header, navigation, docs sidebar, main, footer, skip link) with its CSS in `static/css/site.css`, made for designing on. `seite theme new [name]` scaffolds it (a customized `base.html` needs `--force` and is backed up) and prints the next steps: `/impeccable init` and `/impeccable <design>` when impeccable is installed, otherwise `/seite theme <description>`. `seite theme create` starts from `blank` when the site is on a bundled example. With impeccable installed, its live mode is pointed at `templates/base.html` (add-only).
- New `template-missing-seite-head` warning when a custom `base.html` does not include `seite/head.html`; a theme with its own copy of the SEO head is reported as a legacy theme.
- `seite upgrade` replaces `templates/base.html` with the new version of its bundled theme when it is an unedited copy of any released version (matched by content hash), and keeps edited copies with a one-time notice showing the three include lines. An unedited older copy also counts as that theme for `seite theme new`, `theme apply` and `seite context`.
- **Escaping in the head.** Titles, descriptions and URLs in meta and link attributes are HTML-escaped (`escape_attr`), and JSON-LD values can no longer end the `<script>` element (`<` is written as `\u003c`). Output changes only for values containing `"`, `<`, `>` or a bare `&`. The search script's "no results" text is now a JSON string literal.
- **Breadcrumb JSON-LD fixed (intentional output change).** The `BreadcrumbList` collection crumb now links the collection's real index (its `url_prefix` with the language prefix, e.g. `/blog` or `/es/blog`) with its trailing slash (`/blog/`, `/es/blog/`) instead of `/<collection name>`, which did not exist for collections with a custom prefix; a collection index page ends at the collection crumb (no "Blog > Blog"), and a `base_url` ending in `/` no longer doubles the slash. Pages of root-mounted collections (`pages`) get Home → Page instead of a crumb to a non-existent `/pages`, the homepage no longer has a breadcrumb, and the Home crumb of a translation links that language's homepage. Templates get `page.collection_url`.
- `seite theme export` inlines the stylesheets the theme links from `static/` (e.g. `static/css/site.css`) as `<style>`, so an exported blank-based design works on another site.
- `seite theme create` checks for a nested agent session and a missing agent before it writes any file.
- Default templates: a collection index page is titled "<label> — <site title>" (the homepage keeps the site title); tag and taxonomy term pages use `<h2>` for their item headings (was `<h3>` right under the `<h1>`); trust center "Learn more" links get an `aria-label` naming the certification. Existing sites keep the `templates/index.html` init copied; delete it (if unedited) to use the embedded version with the new title.
- `seite theme export` inlines only real files inside `static/`: a stylesheet href that is absolute (`/static//etc/x.css`), contains `..`, or goes through a symlink is left as a link, with a warning.
- `seite upgrade` also refreshes `templates/index.html` and `templates/trust-index.html` when they are unedited copies of an earlier default (edited copies are kept, with a one-time notice saying what to add). With the `blank` starter, the homepage and collection listings now have an `<h1>` (the site name, via the new optional `site_title` block).

### Audit and determinism

- **`seite audit`**: a free, offline SEO, GEO (AI visibility), accessibility, content and performance audit of the built site — the checks paid SEO crawlers charge for, for small sites. It builds into a scratch directory like `seite check` (or reads an existing output with `--dist <dir>`) and reports findings with stable codes (`seo-…`, `geo-…`, `a11y-…`, `content-…`, `perf-…`, each documented in the [error reference](/docs/errors) and `seite explain`), the page, and the markdown or template file and line to fix. Checks: titles (missing, duplicate, over 60 characters), descriptions (missing, duplicate, under 50 or over 160 characters), canonical, one `<h1>` in `<main>`, heading levels, thin content (under 150 words), orphan pages, broken `#anchors`, `noindex` pages in the sitemap, sitemap vs built pages, image `width`/`height`, `og:image`, hreflang reciprocity; llms.txt presence and completeness, markdown alternates, JSON-LD that parses and has `@type`, robots.txt letting AI search crawlers in, Content-Signal; `<html lang>`, alt text, empty or "read more" links, form labels, button names, skip link, duplicate ids; links to drafts and scheduled posts, undated posts in dated collections; images over 300 KB, pages over 1.5 MB, render-blocking scripts, lazy loading. The score is 100 minus 10 per error and 3 per warning (notices are reported but not scored), counting at most 3 findings per code and 30 points per category. `--json` has a stable shape (`summary` + `findings`), `--category` and `--min-severity` filter, `--fail-on error|warning` sets the exit code for CI. Template problems shown on many pages are reported once. Also available as the read-only MCP tool `seite_audit` and as `/seite audit` in the agent skill (skill version 5); `seite context` points to it. See [Audit](/docs/audit).
- **Byte-identical builds.** The same sources now build to the same bytes every time: `sitemap.xml`, `search-index.json`, `_redirects` and `asset-manifest.json` no longer depend on hash-map order (collections keep their `seite.toml` order, the asset manifest is sorted), and published `.md` copies keep `extra:` keys in source order. No output embeds the build time. `seite build --json` lists collections in sorted order.
- **`[site] timezone` in new sites.** `seite init` writes the system's IANA time zone (from `TZ`, else the OS setting; a commented example when it can't be detected); `seite workspace add` does the same, so "today" for scheduled posts is the same on every machine and in CI. `seite upgrade` doesn't add it, but recommends it once when `[build] schedule = true` has no timezone, and `seite context` reports a `TIMEZONE_UNSET` directive.
- Repeated markdown headings get unique ids (`setup`, `setup-1`, …, like GitHub), so ToC anchors and `id`s no longer collide (`a11y-duplicate-id`).
- Starter content passes the audit: the starter post explains how posts work and what to do next (it was a two-line placeholder), and the trust center, changelog and roadmap starters have full descriptions and enough text.

### Search

- **Full-text search on any static host.** With `[build] search = "full"` (new sites get it from `seite init`) the build writes a search index of every page's text next to the pages: `search/meta.json`, term shards under `search/terms/` (about 8 KB each) and one small file per page for snippets. No service, no API key, no Node. The bundled themes' search box loads it lazily: the browser downloads only the shards holding the words you type and the results it shows, so a query on a 1,000-page site downloads well under 100 KB. Multilingual sites get one index per language.
- **Better results.** All words must match and the last one matches as a prefix while you type (results never blink out mid-word, e.g. at "buildin", and a last word that matches nothing yet keeps the results of the others); titles rank above headings, tags and descriptions, and those above body text. Matching ignores case and accents ("cafe" finds "Café"); English sites also match word forms ("posts" → "post", "running" → "run") and ignore words like "the"; Chinese, Japanese and Korean text is matched by character pairs. Results show a snippet with the matched words highlighted, the arrow keys move through them, Enter opens one and Escape closes the list, and the number of results is announced to screen readers (new UI strings `t.search_result` and `t.search_results`).
- Drafts (even with `--drafts`), scheduled posts, `robots: noindex` pages, unlisted and private collections are never indexed. `seite build --verbose` prints the index size and `seite build --json` reports it as `data.search_index`.
- Existing sites keep today's search (titles, descriptions and tags from `search-index.json`, whose format is unchanged) until they add `search = "full"`; `seite upgrade` mentions it once. `search = false` removes the index and the search box. See [Configuration](/docs/configuration#search) and [Templates](/docs/templates#search) (result markup, `search_mode`, and `{% set search_collections = "docs" %}` before the include to limit a search box to some collections).
- `search/meta.json` is fetched without the HTTP cache, so a new deploy's index is used at once; `seite serve` rebuilds remove shard and page files the new index no longer has.
- The seite.sh site now uses seite's own head, search and script partials, so `seite check --strict` passes on it, and its docs search covers the full text of the docs.
### Social cards

- **Every page gets a social preview card.** With `[og]` (new sites have `generate = true`), the build draws a 1200x630 PNG per page into `dist/og/` (`/posts/hello-world` → `/og/posts/hello-world.png`, translations under `og/<lang>/`) and sets it as `og:image` and `twitter:image` (with `og:image:alt` and `twitter:card` `summary_large_image`). Free, offline and deterministic: SVG rendered with resvg, using a bundled subset of Inter (SIL Open Font License; Latin, Greek, Cyrillic) and never system fonts. Pages with `image:` in their frontmatter keep it.
- Three layouts (`template = "default" | "minimal" | "bold"`), colors from `data/brand.yaml` (background, text, primary) or the active theme unless `background`/`foreground`/`accent` are set, an optional `logo` (SVG or PNG) and `font` (`.ttf`/`.otf`). Long titles wrap to three lines, shrink, then end with an ellipsis.
- Each language's homepage gets a site card (`og/index.png`) that collection indexes, tag pages, 404, drafts and private pages use. Private collections never get cards of their own, so their titles are not published.
- A title with characters the font lacks (CJK, emoji) gets no card of its own instead of empty boxes, with one `og-missing-glyphs` warning; set `[og] font`. Bad colors and missing logo or font files are `og-config-invalid` errors at their line in `seite.toml`.
- Cards are cached in `.seite/cache/og/` by a hash of everything that affects them, so rebuilds only render what changed; `seite serve` re-renders only an edited page's card, and `seite check` renders none. `seite build --json` reports `og_cards` (rendered, cached, missing_glyphs).
- Cards are safe with untrusted sites: logo and font paths must be real files inside the site (no symlinks, no `..`), logos are capped at 1 MB and 4096 px, and an SVG logo can't load other files (only inline `data:` images). The cache has one directory per output and each full build deletes entries it no longer uses. `og:image:alt` is the page title on a page's own card and the site title on the site card. The reading-time label uses the site's `min_read` UI string (untranslated languages get "N min", no English).
- The bundled font keeps its licence metadata, `seite --licenses` prints the SIL Open Font License, and release archives include `LICENSE-Inter-OFL.txt`.
- `seite og preview <page|/>` renders one card to `.seite/cache/og-preview.png` (`--out`, `--template`) to try colors and layouts.
- seite.sh itself now turns on `[og]`, so every docs page, post and changelog entry has its own card in the site's brand colors.
- Existing sites are unchanged until they add `[og]`; `seite upgrade` mentions it once. `seite audit`'s `seo-og-image-missing` no longer fires for pages with a generated card. The `/seite brand` skill reference says brand colors and the logo feed the cards (skill version 6).

### Dev server: live errors for people and agents

- Live reload uses Server-Sent Events (`/__seite/events`) instead of polling once a second; browsers without `EventSource` still poll `/__livereload`.
- **Build-error overlay.** When a rebuild fails, the open page shows every diagnostic (`file:line:col severity[code] message` and its hint) in a dismissable panel, and reloads once the next build succeeds. A failed first build no longer stops `seite serve`.
- **Browser errors reach the terminal.** Uncaught errors, unhandled promise rejections and `console.error` calls in preview pages are printed as `browser: <page> <kind>: <message>` (control characters and ANSI escapes stripped, repeats counted, rate-limited) and kept for `seite preview`.
- **`seite preview`** prints the running dev server's URL, its last build outcome (compiler-style, like `seite check`) and the browser errors (marked as untrusted page output), and exits 1 when no server runs or the last build failed; `--json` for scripts, `--clear-browser-errors` to start fresh. `seite context` shows the same in its dev-server line and adds `DEV_BUILD_FAILED` / `BROWSER_ERRORS` directives. The `/seite preview` skill reference tells agents to run it after visible changes.
- **MCP over HTTP.** While `seite serve` runs, the site's MCP server is also at `http://localhost:<port>/__seite/mcp` for clients that support HTTP servers (`{"type": "http", "url": "…"}`). It only answers local MCP clients (loopback connection and Host, no browser `Origin`, so no web page can call it, JSON bodies only, no CORS headers) and is off when the server listens on the network. `seite_build` through it rebuilds with the dev configuration.
- **Runtime MCP tools:** `seite_get_errors`, `seite_get_preview_url`, `seite_list_routes` and `seite_reload`. Under `seite mcp` over stdio they ask the running dev server, or say "no dev server running; start it with `seite serve`".
- `GET /__seite/status` returns the server's pid, URL, last build and browser errors as JSON (requests must address the server by a loopback name or IP address).
