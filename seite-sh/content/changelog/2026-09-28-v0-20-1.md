## Password access: fail closed on Cloudflare Pages

Protected pages and files are deployed as static assets, and the password Worker is what keeps them private. On the Workers Free plan, a Pages project set to **Fail open** serves static assets without running the Worker once the daily Workers request allowance runs out. Cloudflare's API defaults new projects to fail open, so a busy protected site could serve its private content without a password.

- `seite access set-password` and `seite deploy --setup` now set production and preview to **Fail closed** on every Pages project that holds protected content.
- `seite deploy` adds a **Cloudflare fail closed** pre-flight check. It reads the setting through the Cloudflare API and offers to fix it. If the setting still fails open or can't be verified, the deploy stops unless you confirm interactively or pass `--skip-checks`. `--yes` applies the fix, but it never skips this check.
- Cloudflare API calls now honor `CLOUDFLARE_ACCOUNT_ID`. When your `wrangler` login has more than one account, seite asks you to set it instead of picking the first account.

**If you already use password access**, run `seite deploy` once to verify and fix each project. If you deploy another way, set **Workers & Pages → project → Settings → Runtime → Fail open / closed** to **Fail closed** in the Cloudflare dashboard. See [Password-protecting paths and subdomains](/docs/deployment#set-every-protected-project-to-fail-closed).

## Correct URLs in the internal links map

`context/internal-links-map.md` now resolves URLs the same way `seite build` does. It respects each collection's `url_prefix` (posts under `/blog` are listed as `/blog/…`, root pages as `/about` instead of `/pages/about`), `slug:` frontmatter overrides, and translations. Drafts and private collections are left out, and collections in their own subdomain are listed with absolute URLs. If `seite.toml` can't be loaded, the existing map is kept and a warning is shown.

`seite skill update` now regenerates the map whenever `context/` exists, even when no skill packs are installed. Before, it stopped at "No skill packs installed. Nothing to update." and never refreshed the map.
