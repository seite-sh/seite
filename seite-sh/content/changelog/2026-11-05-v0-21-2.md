A performance and bug-fix release. Upgrade with `seite self-update`; no `seite upgrade` step is needed, and the generated site is byte-for-byte the same.

## Performance

- **Pages are written once.** Before, `seite build` wrote every page, read it back to add code-copy buttons, analytics and image `srcset`s and check its links, then wrote it again. Pages now stay in memory until that step and go to disk once.
- **Generated files are written in parallel.** Pages and their `.md` copies were rendered in parallel but written one at a time. The `.md` copies are now written in the background while the homepage, listings, feeds and sitemap render, and tag and taxonomy pages render in parallel.
- **Fewer writer threads on macOS.** Creating files stops scaling after a few threads on macOS, and more threads only contend in the kernel, so seite writes with 4 threads there.
- On a 10,000-post benchmark site (Apple M4 Pro, median of 5 runs) a full build went from 1.81 s to 718 ms with minimal templates, and from 2.39 s to 882 ms with the default theme; 1,000 posts went from 186 ms to 88 ms. Because pages stay in memory until they are written, peak memory rises by 2–14% (10,000 posts: 304 to 311 MiB), and by 15% with the default theme (595 to 683 MiB).
- Broken-link warnings are now listed in path order, the same on every file system.

## Fixes

- **`seite serve` rebuilds for edits saved during a rebuild.** The dev server dropped every file change that arrived while a rebuild ran, including a save made right after the browser reloaded, so the page kept showing the old version until the next edit. It now rebuilds again for those changes. Changes the build itself makes are still ignored.
- **Workspace `seite serve` rebuilds every site that changed.** When files in two sites changed at once, only the first site was rebuilt; now each site with a change is.
