seite 0.21 is built so a coding agent (Claude Code, Codex, OpenCode, Cursor, Gemini CLI, GitHub Copilot) can run a site end to end without API keys or paid services: a compact AGENTS.md, one routed `/seite` skill, two-tier check hooks, CLI equivalents of every MCP tool, and a dev server that reports build and browser errors. The site side gains full-text search, generated social cards, `seite audit`, taxonomies and series, typed frontmatter, scheduled publishing, importers, Git-based CMS setup and Tailwind without Node. It includes the 0.20.2 security fixes.

## Upgrading from 0.20

Run `seite self-update`, then `seite upgrade` in the site root.

**What `seite upgrade` does automatically**

- Adds missing harness files for the site's agents and merges into existing configs (JSON: adds keys only; Codex TOML: appends a table, comments kept); never deletes files of deselected agents. Includes `.claude/launch.json` for the Claude desktop preview pane.
- Writes the `/seite` skill (version 7) with its `reference/` files for every provider, replacing older seite-written copies.
- Removes the retired `theme-builder`, `brand-identity` and `landing-page` skills and the `design-prompts` rule only when unmodified (content hash); edited copies are kept with a one-time notice.
- Prunes the `AGENTS.md` sections 0.20 wrote for the retired skills and the serve REPL when unedited (replaced by a one-line `/seite theme|brand|landing` pointer), and refreshes the `<!-- seite:agent-setup -->` and `<!-- seite:context-rules -->` blocks.
- Adds each check-hook tier (turn-end, after-edit) not yet recorded in `.seite/config.json` `hooks_installed`, so a hook you deleted stays deleted.
- Narrows the 0.20 agent permissions, when still exactly as seite wrote them, to `seite theme apply` and `seite theme list`, and allows the new agent-facing commands (`seite context`, `docs`, `page`, `search`, `stats`, `templates`, `frontmatter`, `explain`, `hooks`).
- Replaces `templates/base.html`, `post.html`, `index.html` and `trust-index.html` when they are unedited copies of a released default (matched by content hash). Edited copies are kept with a one-time notice saying what to add.
- Writes `.seite/docs/` for the installed version and gitignores `.seite/docs/` and `.seite/dev.json`.
- With `schedule = true`, adds the daily cron to unedited generated GitHub Actions workflows; with `[build.tailwind]`, adds `SEITE_TRUST_PROJECT=1` to unedited workflows and `netlify.toml`. Edited files get a notice explaining the change.
- Shows one-time notices for the new opt-in features below, Copilot support, and a missing `[site] timezone` when `schedule = true`.

**Manual opt-ins** (existing sites build exactly as before without them)

- `[build] search = "full"` for the full-text index ([Search](#search)).
- `[og] generate = true` for social cards ([Social cards](#social-cards)).
- `[build] schedule = true`, ideally with `[site] timezone`, for scheduled publishing.
- `seite upgrade --mcp` to keep or add MCP config for coding agents; without it upgrade never touches existing MCP config.
- `seite upgrade --agents …,copilot` to add GitHub Copilot (sites with no stored selection keep 0.20's five agents).
- `seite theme apply <name>` for a site whose `base.html` was edited, to get the `seite/` head partials, view transitions and contrast fixes; or add the include lines from [Templates](/docs/templates) by hand.
- `[build.tailwind]` needs `seite trust` once per machine (CI: `SEITE_TRUST_PROJECT=1`).
- `[[taxonomies]]`, `[collections.fields.*]` schemas, `[comments]`, `[newsletter]`, `[deploy] markdown_negotiation`, `seite cms setup`: add when wanted.

**Breaking and output changes**

- MCP is no longer wired in for coding agents by default (`--mcp` opts in). The `seite://mcp-config` resource is removed.
- `seite agent` is a thin launcher: the prompt is passed as-is, with no injected context, tool allowlist or MCP flags. `--yes` / `SEITE_YES` no longer add auto-approve flags; use `seite agent --once --auto-approve` from an interactive terminal. `seite agent` and `seite theme create` refuse to run inside an agent session.
- Generated permissions no longer allow `seite theme create` or `seite agent`.
- `.md` URLs are served as `text/markdown; charset=utf-8` (was `text/plain`).
- Every published `.md` copy starts with a line pointing to `llms.txt`, `llms-full.txt` and `sitemap.md`.
- `BreadcrumbList` JSON-LD links real collection indexes; the homepage has no breadcrumb.
- Collection index pages are titled "<label> — <site title>"; term pages use `<h2>` item headings.
- `robots.txt` allows and blocks more crawlers and adds a `Content-Signal` line.
- Repeated headings get unique ids (`setup`, `setup-1`), which changes those anchors.
- Head attributes are HTML-escaped and JSON-LD escapes `<`; output differs only for values with `"`, `<`, `>` or a bare `&`.
- An `aliases:` entry that would overwrite a built file is skipped with an `alias-collision` warning.
- `seite build --json` lists collections in sorted order.

No commands or flags were removed. Run `seite upgrade --agent` to have your coding agent apply the manual steps from these notes and run `seite check` and `seite build` until clean.

## Agents run the site themselves

- **One routed `/seite` skill** (`$seite` in Codex). `SKILL.md` is short and points to one `reference/<command>.md` per command: check, new, audit, preview, build, deploy, theme, brand, landing, collection, upgrade, hooks. `theme-builder`, `brand-identity`, `landing-page` and the `design-prompts` rule are folded into `/seite theme`, `/seite brand` and `/seite landing`. Verification is bounded: check, fix everything, check once more, stop. Version 7 checks that `seite` 0.21 or newer is installed (asking before installing, suggesting `seite self-update` when older) and says when a directory isn't a seite site.
- **Compact AGENTS.md** (about 3.5 KB): what the site is, layout, collections, content format, hard rules, and the workflow (`seite context`, then `/seite`). The command list, REPL docs, MCP tool list and docs links are gone; docs for the installed version are in `.seite/docs/`, which is gitignored and written lazily by `seite context` and `seite docs` (rewritten for another seite version, with pages it no longer ships pruned).
- **Two-tier check hooks.** After each edit, `seite check --hook <agent> --post-edit` checks only the edited file; at the end of a turn, the full check runs. Hook commands exit 0 silently when `seite` isn't installed. `seite hooks on|off|status [--tier stop|post-edit|all]` manages them; `hooks_installed` records each tier (`claude`, `claude:post-edit`). `seite hooks off` removes only hook entries whose command seite generated, and deletes OpenCode's plugin only while unedited. Hook messages start with a line saying they are `seite check` output about the site's files, and each diagnostic line is cut at 300 characters. The Cursor hook always gets a JSON document on stdout, including when Cursor runs Claude Code's hooks and on internal errors.
- **Gemini CLI** (`--agents gemini`): `GEMINI.md` imports `AGENTS.md`, `.gemini/settings.json` carries the hooks, `/seite` is `.gemini/commands/seite.toml`. `seite agent --with gemini` launches it.
- **GitHub Copilot** (`seite init --agents copilot`, `seite upgrade --agents …,copilot`): Copilot reads `AGENTS.md` itself; seite writes the skill to `.agents/skills/seite/`, rules to `.github/instructions/*.instructions.md` (`applyTo` globs) and hooks to `.github/hooks/seite.json`. With `--mcp` it shares Claude Code's `.mcp.json`. `seite agent --with copilot` runs `copilot -p` (`--once`) or `copilot -i`; `--auto-approve` adds `--allow-all-tools`. `seite check --hook copilot` speaks Copilot's hook protocol. `seite init` without `--agents` sets up all six agents.
- **Without `seite init`.** `npx skills add seite-sh/seite` installs the `/seite` skill and its references into any agent the [skills CLI](https://skills.sh) supports. The Claude Code plugin (`/plugin marketplace add seite-sh/seite`, then `/plugin install seite@seite`) installs the skill and both check hooks, no MCP server. Its hooks run in every project, so they are scoped: silent outside a seite site, the end-of-turn check runs only after an edit inside the site, and they step aside when `.claude/settings.json` or `.claude/settings.local.json` has the same seite hook. Both are generated by the hidden `seite skill export`, and a test fails when the checked-in copies drift.
- **MCP is opt-in for coding agents** (`--mcp` on `init` and `upgrade`). `seite mcp --dir /path/to/site` is documented for Claude Desktop.
- **`seite agent`**: `claude "<prompt>"`, or `claude -p` with `--once`. **`seite theme create`** runs `/seite theme <description>`, or points to `/impeccable` when it is installed, and checks for a nested session and a missing agent before writing any file.
- **`seite context`**: once-per-session orientation (site, collections with counts, theme, local docs, skill packs, agents and hooks, running dev server) ending in `NAME: message` directives (`UPGRADE_AVAILABLE`, `NO_STOP_HOOK`, `ADDON_SUGGESTION`, `TIMEZONE_UNSET`, `DEV_BUILD_FAILED`, `BROWSER_ERRORS`). Works outside a project.
- **CLI for every MCP capability**, with `--json` and the same code as the MCP tool: `seite docs [query] [--topic slug]`, `seite page <path|url>`, `seite search <query>`, `seite stats`, `seite templates`, `seite frontmatter set|unset`. At a workspace root without `--site`, these and `seite context` say "this is a workspace: pass --site <name>" and list the sites.
- **`seite explain <code>`** and an [error reference](/docs/errors) with one section per diagnostic code. JSON diagnostics gain `docs_url`; `seite check` ends with a pointer to `seite explain` when it reports problems.
- `seite check --file` reports each skipped path (missing, outside the site, not a content/template/data file) as a `check-file-skipped` warning; `--strict` fails on them.
- New `template-markdown-link` warning for custom templates that still build `{{ page.url }}.md` links, with `page.markdown_url` as the hint.
- **`seite upgrade --agent [--with <agent>]`** upgrades, then builds a migration brief from the release notes since the project's recorded version (all entries, capped at about 48 KB, when unknown): what changed automatically, the notes, and instructions to apply manual steps and run `seite check` and `seite build` until clean. In an agent session, with `--json` (`data.brief`) or without a terminal it prints the brief; from a terminal it saves `.seite/upgrade-brief.md` (gitignored) and starts the chosen agent with a one-line prompt to read it, never with auto-approve flags. Cannot be combined with `--check`. `/seite upgrade` uses it. The "Kept …" notices for edited legacy files print once, never under `--check`.
- **Skill packs.** `seite skill install|update|remove impeccable` installs the impeccable design skill for the project's agents through its npm installer (pinned version, fetched into a temp directory so project npm config can't swap it, then `impeccable install --providers=<agents> --scope=project`), after asking; it passes `github` for Copilot, and `seite skill list` shows it. `seite skill install seomachine` downloads from one pinned upstream commit (`120e7b4`, 2026-10-23) with a SHA-256 per file compiled in; everything is verified before anything is written, and `seite skill update seomachine` moves to the pin of the running seite, never upstream `main` (SEOMachine is MIT-licensed). Its 25 skills go to each selected agent's skills directory (`.claude/skills/`, or `.agents/skills/` with `name`/`description` frontmatter only); subagents and slash commands are Claude Code-only. Agents come from `.seite/config.json`, overridable with `--agents`. The manifest records the commit, agents and a hash per file; update and remove keep edited files and never overwrite files seite did not install. Old manifests keep working.

## Dev server and `seite preview`

- Live reload uses Server-Sent Events (`/__seite/events`); browsers without `EventSource` still poll `/__livereload`.
- **Build-error overlay.** When a rebuild fails, the open page shows every diagnostic (`file:line:col severity[code] message` and hint) in a dismissable panel, and reloads once the next build succeeds. A failed first build no longer stops `seite serve`.
- **Browser errors reach the terminal.** Uncaught errors, unhandled rejections and `console.error` calls are printed as `browser: <page> <kind>: <message>` (control characters and ANSI escapes stripped, repeats counted, rate-limited) and kept for `seite preview`.
- **`seite preview`** prints the running server's URL, its last build outcome (compiler-style) and the browser errors (marked as untrusted page output), and exits 1 when no server runs or the last build failed; `--json`, `--clear-browser-errors`. The `/seite preview` reference tells agents to run it after visible changes.
- `seite serve` records itself in `.seite/dev.json` (removed on stop, Ctrl-C or SIGTERM); a second `seite serve` in the same directory prints the running URL and exits unless `--force-new`. `GET /__seite/status` returns pid, URL, last build and browser errors as JSON (loopback Host only).
- **MCP over HTTP** at `http://localhost:<port>/__seite/mcp` while `seite serve` runs (`{"type": "http", "url": "…"}`). It answers only local clients (loopback connection and Host, no browser `Origin`, JSON bodies, no CORS headers) and is off when the server listens on the network. `seite_build` through it uses the dev configuration.
- **Runtime MCP tools**: `seite_get_errors`, `seite_get_preview_url`, `seite_list_routes`, `seite_reload`. Under stdio `seite mcp` they ask the running dev server, or say "no dev server running; start it with `seite serve`".

## Content model

- **Taxonomies.** `[[taxonomies]]` adds groupings beyond tags: `name`, `label`, `url_prefix` (default `/<name>`), `feed` (default on), `paginate`, `template`/`term_template`. Pages assign terms with a top-level key (`categories: [Rust, Web]`). Each gets a term index (`/categories/`), a page per term (paginated with `paginate`), per-term RSS and Atom feeds whose `<id>`, alternate link and channel `<link>` are the term page, per-language versions (`/es/categories/...`) and sitemap entries. New templates `taxonomy.html` and `term.html`. Tags are unchanged unless `[[taxonomies]] name = "tags"` opts them into feeds and pagination.
- **Related pages.** `page.related` lists up to 3 pages from the same collection and language sharing tags or terms (a shared category counts twice a shared tag; ties go to the closest date). `[build] related = N` sets the size; `0` (site-wide or per collection) turns it off. Computed in parallel; in a group of more than 200 pages a term on more than 20% of them no longer relates pages by itself.
- **Series.** `series: "Rust from scratch"` (plus `series_order`) fills `page.series` (ordered parts, position, previous and next) and adds `/series/<slug>/`. A list uses its first entry and `series_order` accepts numeric strings; other shapes are ignored. Nothing is generated when no page uses `series`. `seite serve` re-renders the other parts of a series when one changes, across collections.
- The default `post.html` shows categories, a "Part 2 of 5" series box and a "Related" list, styled by every bundled theme; tag links follow the tags taxonomy's `url_prefix`. New UI strings `t.categories`, `t.related`, `t.series`, `t.series_part`. Edited `post.html` copies get a notice pointing at the snippet in [Templates](/docs/templates).
- Search, stats and templates commands (and MCP tools) report taxonomies and series. Published `.md` copies include taxonomy keys.
- Diagnostics: `taxonomy-url-collision` (error), `taxonomy-reserved-name` (warning, e.g. `extra`), `series-url-collision` (warning).
- **Typed frontmatter schemas.** `[collections.fields.<name>]` declares `type` (string, text, number, integer, bool, date, datetime, url, image, enum, list, object), `required`, `enum`, `items`, `min`/`max`, `pattern`, `default`, `description`. Build, check, `check --file` and the after-edit hook report `frontmatter-schema` errors at the exact line with expected vs found and the description as hint; `strict_fields = true` adds `frontmatter-schema-unknown` warnings. Built-in keys and taxonomy names validate at the top level; custom fields may sit at the top level or under `extra:` (both is an error), read as `page.extra.<name>`, and appear in published `.md` copies (undeclared keys never do). `seite new` writes defaults and placeholders; MCP create/update refuse violations (new custom fields go under `extra:`, existing ones are edited in place). Schemas show in `seite templates`, `seite context` and `seite_list_templates`. New sites get small presets (types and descriptions only); `seite upgrade` adds none.
- **Scheduled publishing** (`[build] schedule = true`, written by `seite init`). In dated collections, a future `date` hides a post from every output until that day; `expires:` takes it down after its date. `seite build --future`, `[build] future = true` and `seite serve` include scheduled posts. "Today" follows `[site] timezone` (IANA name or offset), else the local date, the same clock `seite new`/`init`/MCP create use. Build, serve and check print "N scheduled posts hidden; next goes live <date> (<title>)". Links to hidden posts are `link-to-scheduled` warnings (`--future` to preview); scheduled posts are still validated. `seite stats` adds expired and next scheduled posts. Generated GitHub Actions workflows rebuild daily (`cron: '17 5 * * *'`). `seite init` and `seite workspace add` write the system's IANA zone (from `TZ` or the OS; a commented example when undetectable).
- **External link check.** `seite check --external` checks external links in the rendered site (8 at a time, 2 per host, 10 s timeout, HEAD then GET, up to 5 redirects), caches working links for 7 days in `.seite/cache/links.json` (gitignored), skips bot-blocking hosts plus `[check] external_skip`, and reports `external-link-broken` / `external-link-unreachable` warnings (errors with `--strict`) at the source line.
- **Byte-identical builds.** `sitemap.xml`, `search-index.json`, `_redirects` and `asset-manifest.json` no longer depend on hash-map order (collections keep `seite.toml` order, the manifest is sorted); `.md` copies keep `extra:` keys in source order; no output embeds the build time.
- Repeated headings get unique ids (`setup`, `setup-1`, like GitHub), so ToC anchors no longer collide.
- **Redirects never replace pages.** `seite build` skips an `aliases:` entry that would overwrite a written file (page, index, feed) with an `alias-collision` warning at the file and line.

## Search

- **Full-text search on any static host.** With `[build] search = "full"` (new sites) the build writes `search/meta.json`, term shards under `search/terms/` (about 8 KB each) and a small file per page for snippets. No service, API key or Node. The bundled search box loads only the shards for the typed words, so a query on a 1,000-page site downloads well under 100 KB. One index per language.
- **Better results.** All words must match, the last as a prefix while typing (results never blink out mid-word, and a last word with no match keeps the others' results); titles rank above headings, tags and descriptions, those above body text. Case- and accent-insensitive; English matches word forms and ignores stop words; CJK is matched by character pairs. Snippets highlight matches, arrow keys, Enter and Escape work, and the result count is announced to screen readers (`t.search_result`, `t.search_results`).
- Drafts (even with `--drafts`), scheduled posts, `noindex` pages, unlisted and private collections are never indexed. `seite build --verbose` prints the index size; `--json` reports `data.search_index`.
- Without `search = "full"`, search stays as before (`search-index.json`, format unchanged). `search = false` removes the index and the search box. See [Configuration](/docs/configuration#search) and [Templates](/docs/templates#search) (`search_mode`, result markup, `{% set search_collections = "docs" %}`).
- `search/meta.json` bypasses the HTTP cache so a new deploy is used at once; `seite serve` removes shard and page files the new index no longer has.
- The seite.sh site uses seite's own head, search and script partials, passes `seite check --strict`, and its docs search covers the full docs text.

## Social cards

- With `[og] generate = true` (new sites), the build draws a 1200x630 PNG per page into `dist/og/` (`/posts/hello-world` → `/og/posts/hello-world.png`, translations under `og/<lang>/`) and sets `og:image`, `twitter:image`, `og:image:alt` and `summary_large_image`. Offline and deterministic: resvg with a bundled Inter subset (SIL OFL; Latin, Greek, Cyrillic), never system fonts. Pages with `image:` keep it.
- Three layouts (`template = "default" | "minimal" | "bold"`); colors from `data/brand.yaml` or the active theme unless `background`/`foreground`/`accent` are set; optional `logo` (SVG or PNG) and `font` (`.ttf`/`.otf`). Long titles wrap to three lines, shrink, then ellipsize.
- Each language's homepage gets a site card (`og/index.png`) used by collection indexes, tag pages, 404, drafts and private pages; private collections never get their own cards. `og:image:alt` is the page title or the site title. The reading-time label uses `min_read` (untranslated languages get "N min").
- A title with glyphs the font lacks gets no card and one `og-missing-glyphs` warning (set `[og] font`). Bad colors and missing logo or font files are `og-config-invalid` errors at their `seite.toml` line.
- Cards are cached in `.seite/cache/og/` (one directory per output, pruned on full builds); `seite serve` re-renders only an edited page's card, `seite check` renders none. `seite build --json` reports `og_cards` (rendered, cached, missing_glyphs).
- Logo and font must be real files inside the site (no symlinks, no `..`); logos are capped at 1 MB and 4096 px; SVG logos load only inline `data:` images.
- `seite og preview <page|/>` renders one card to `.seite/cache/og-preview.png` (`--out`, `--template`). `seite --licenses` prints the font licence; release archives include `LICENSE-Inter-OFL.txt`. `seo-og-image-missing` no longer fires for pages with a generated card; `/seite brand` notes that brand colors and logo feed the cards. seite.sh uses `[og]` itself.

## Audit

- **`seite audit`**: a free, offline SEO, GEO, accessibility, content and performance audit. It builds into a scratch directory (or reads `--dist <dir>`) and reports findings with stable codes (`seo-…`, `geo-…`, `a11y-…`, `content-…`, `perf-…`, all in the [error reference](/docs/errors) and `seite explain`), the page, and the markdown or template line to fix. Checks: titles (missing, duplicate, over 60 chars), descriptions (missing, duplicate, under 50 or over 160), canonical, one `<h1>` in `<main>`, heading levels, thin content (under 150 words), orphan pages, broken `#anchors`, `noindex` pages in the sitemap, sitemap vs built pages, image `width`/`height`, `og:image`, hreflang reciprocity; llms.txt presence and completeness, markdown alternates, JSON-LD validity and `@type`, robots.txt for AI search crawlers, Content-Signal; `<html lang>`, alt text, empty or "read more" links, form labels, button names, skip link, duplicate ids; links to drafts and scheduled posts, undated posts in dated collections; images over 300 KB, pages over 1.5 MB, render-blocking scripts, lazy loading.
- Score: 100 minus 10 per error and 3 per warning (notices unscored), at most 3 findings per code and 30 points per category. Stable `--json` (`summary` + `findings`), `--category`, `--min-severity`, `--fail-on error|warning` for CI. Template problems on many pages are reported once. Pass-through HTML under `static/` is skipped. Also the read-only MCP tool `seite_audit` and `/seite audit`. See [Audit](/docs/audit).
- Starter content passes the audit: a real starter post, and trust center, changelog and roadmap starters with full descriptions.

## Import from WordPress, Ghost, Jekyll and Hugo

`seite import <wordpress|ghost|jekyll|hugo> <source>` takes a WordPress WXR export, a Ghost JSON export, or a Jekyll or Hugo directory. See [Import](/docs/import).

- **Content.** Posts go to `posts`, pages to `pages` (`--collection`, `--pages-collection`; a missing collection stops the import and names `seite collection add`). Title, date, updated, description, tags, categories (into a `categories` taxonomy when configured, else tags), featured image, author (`extra.author`) and drafts are mapped and checked against the schema. WordPress and Ghost HTML becomes Markdown; `[caption]`, figures, `[embed]` and YouTube/Vimeo embeds become shortcodes; Jekyll `{% highlight %}`, `{% raw %}`, `{% link %}`, `{% post_url %}` and Hugo `youtube`, `vimeo`, `gist`, `figure`, `highlight`, `ref` are converted. Anything else stays in place, inert, reported with its source line.
- **Old URLs keep working.** WordPress permalinks and old slugs, Ghost `/<slug>/`, Jekyll permalink styles and Hugo `url`/`[permalinks]`/`aliases` become `aliases:`.
- **Images** are downloaded (only from the export's own site or `--allow-host`; `image/*`, 20 MB per file, 500 MB total, redirects only to allowed hosts) or copied (never from outside the source directory, symlinks included) into `static/images/imported/<slug>/`, once per content.
- **Safe to re-run.** `--dry-run` writes nothing, existing files are skipped unless `--force`, drafts need `--drafts`, and the same source gives byte-identical files.
- **A report for your agent**, printed (`--json` for all of it) and written to `.seite/cache/import-report.md` as a checklist; then run `seite check` and `/seite check`.

## Git-based CMS, comments and newsletter

- `seite cms setup pages-cms` writes `.pages.yml` for [Pages CMS](https://pagescms.org); `seite cms setup decap` writes `static/admin/index.html` and `config.yml` for [Decap CMS](https://decapcms.org). Both are free and edit markdown through GitHub. Every collection becomes a CMS collection with the right folder and naming (`{year}-{month}-{day}-…` for dated ones); fields come from built-in frontmatter plus your schema (enums become selects). The Decap page loads pinned Decap CMS 3.16.3 with Subresource Integrity and is `noindex`; the repo comes from the `origin` remote. Existing files are overwritten only with `--force`, which backs up to `.seite/cache/backups/`. A site in a repository subdirectory gets repository-relative paths and `.pages.yml` at the repository root. `seite check` warns (`cms-config-stale`) when the config names a missing collection folder. See [Git-based CMS](/docs/cms).
- **`{{< comments() >}}`** embeds giscus or utterances from `[comments]`; themes can `{% include "seite/comments.html" %}`.
- **`{{< newsletter() >}}`** renders an accessible Buttondown or Kit subscribe form from `[newsletter]`: a plain form POST, no third-party JavaScript, styled by every bundled theme (`newsletter_email` / `newsletter_submit` UI strings).
- Both validate their settings on load (`config-invalid`) and escape them; without their section they render nothing and warn (`comments-not-configured`, `newsletter-not-configured`).
- Shortcode diagnostics after a fenced code block report the right line, and an empty fenced block no longer hides every shortcode after it.

## Tailwind CSS without Node and CSS bundling

```toml
[build.tailwind]
input = "static/css/tailwind.css"   # entry CSS with @import "tailwindcss"
output = "css/tailwind.css"          # → /static/css/tailwind.css
```

- seite downloads one pinned Tailwind v4 standalone CLI (v4.3.3) on first use, verifies its SHA-256 against a checksum built into seite, and caches it per user. `SEITE_TAILWIND_BIN` in your environment selects your own executable; `seite.toml` can never choose a program to run. The CSS is fingerprinted like other static files and rebuilt on every rebuild. Errors: `tailwind-failed`, `tailwind-download-failed`.
- Tailwind plugins run project JavaScript, so it runs only for trusted projects: `seite trust` once in the site root (stored per user; `--revoke`, `--list`), else `tailwind-untrusted`. CI sets `SEITE_TRUST_PROJECT=1`; generated workflows and `netlify.toml` include it for Tailwind sites. Only `seite build`, `seite serve` and MCP `seite_build` run it; check, audit, hooks and other MCP tools treat the entry as plain CSS.
- `seite theme new --tailwind` adds the table, writes the entry CSS with explicit `@source` paths, links the output from `base.html`, and trusts the project only when run by hand at a terminal outside an agent session.
- With `minify = true`, leading local `@import "base.css";` / `@import url(parts/grid.css);` statements are inlined (each file once, up to 2 MB). A stylesheet is left as written when any import is remote, media-qualified, `layer()`/`supports()`, circular, outside `static/`, or a file with relative `url(...)`.

## Themes

- **seite owns the SEO head; themes own layout and CSS.** Embedded partials under `seite/`: `head.html` (meta, canonical, Open Graph, Twitter, JSON-LD, hreflang, feed/`llms.txt`/markdown links, robots, KaTeX), `search.html`, `search-script.html`, `lang-switcher.html`, `scripts.html`. Bundled themes include them, so SEO, GEO and search fixes ship with the binary. Rendered pages are unchanged except: `landing` and `terminal` use the DOM-based search script (titles no longer inserted as HTML; terminal's meta separator is `·`), `docs`' language switcher is a `<nav>`, and `landing`, `terminal`, `magazine` and `academic` load the KaTeX stylesheet when `math` is on. `templates/seite/<name>.html` overrides a partial (and stops receiving fixes). `template-missing-seite-head` warns when a custom `base.html` lacks `seite/head.html`.
- **Starters and a gallery.** `seite init` offers `default`, `docs`, `landing` and the new `blank` (`--theme`; a docs-only site gets `docs`). `minimal`, `dark`, `brutalist`, `bento`, `terminal`, `magazine` and `academic` are an embedded gallery for `seite theme apply`; `seite theme list` shows both.
- **Design your own.** `blank` is a bare semantic layout with CSS in `static/css/site.css`. `seite theme new [name]` scaffolds it (a customized `base.html` needs `--force` and is backed up) and suggests `/impeccable init` and `/impeccable <design>` when impeccable is installed, else `/seite theme <description>`. `seite theme create` starts from `blank` on a bundled example. Impeccable's live mode is pointed at `templates/base.html`. With `blank`, the homepage and listings have an `<h1>` (new `site_title` block). An unedited older bundled `base.html` counts as that theme for `theme new`, `theme apply` and `seite context`.
- `seite theme export` inlines linked stylesheets from `static/` as `<style>`, only for real files inside `static/` (absolute, `..` or symlinked hrefs stay links, with a warning).
- **View transitions** in every bundled theme and `blank` (`@view-transition { navigation: auto; }`), skipped under reduced motion.
- **Escaping in the head.** Meta and link attributes use `escape_attr`; JSON-LD writes `<` as `<`; the "no results" search text is a JSON string literal.
- **Breadcrumb JSON-LD.** The collection crumb links the real index (`url_prefix` with language prefix and trailing slash: `/blog/`, `/es/blog/`) instead of `/<collection name>`; collection indexes end at that crumb; a `base_url` ending in `/` no longer doubles the slash; root-mounted collections get Home → Page; the homepage has none; a translation's Home crumb links its language homepage. Templates get `page.collection_url`.
- **Markdown alternate links that resolve.** `page.markdown_url` is the path of the markdown copy actually written (`/posts/hello-world.md`, `/posts/index.md`, `/index.md` when `content/pages/index.md` exists), unset otherwise; bundled themes emit the link only when set, replacing `.md` appended to the URL (`/.md`, `/posts/.md`, links on tag, paginated and 404 pages):

  ```html
  {% if page.markdown_url %}<link rel="alternate" type="text/markdown" title="Markdown" href="{{ site.base_url }}{{ page.markdown_url }}">{% endif %}
  ```

- Default templates: collection indexes are titled "<label> — <site title>" (homepage keeps the site title); term pages use `<h2>` item headings; trust center "Learn more" links get an `aria-label`.
- **Contrast.** Skip-link hover kept text readable in default (white, plus distinct `h1`–`h3` sizes), dark, landing, magazine and brutalist (was yellow on yellow). Muted text in minimal, academic, bento, landing and dark meets WCAG AA 4.5:1. Magazine tag links are 0.7rem (was 0.68rem, under the 11px floor).

## Markdown for readers' agents

- **Every `.md` copy points to the site index**: after the frontmatter, pages, collection and homepage `index.md` start with `> Index of this site for agents: [llms.txt](…). Full text: [llms-full.txt](…). All pages: [sitemap.md](…).` (absolute URLs; other languages link `/<lang>/llms.txt`). `llms-full.txt` is unchanged.
- **`/sitemap.md`**: every page's markdown URL with title and description, one section per collection and language, from `sitemap.xml`'s pages minus `noindex` and drafts; `llms.txt` links it.
- **`Accept: text/markdown`.** `seite serve` answers requests preferring `text/markdown` over `text/html` with the markdown copy and sends `Vary: Accept`; browsers and `*/*` get HTML.
- **Cloudflare Pages.** The `[access]` Worker negotiates after its password check. Other sites opt in with `[deploy] markdown_negotiation = true` (a `_worker.js` and `_routes.json`; static assets, cards and the search index skip the Worker). Off by default because every page request becomes a Functions request (Workers Free: 100,000 a day); `seite build` warns when set for another target, or when `_headers`/`_redirects` exist (not applied to Worker responses). Only plain paths negotiate (no `%` escapes, `//`, backslashes or dot segments), and the exact `.md` path is authorized before it is fetched. Netlify and GitHub Pages get none; [Deployment](/docs/deployment#markdown-for-agents) explains why and has a Netlify Edge Function example.
- **robots.txt** keeps its policy (allow AI search and user fetches, block training): `Claude-SearchBot`, `Claude-User` and `Perplexity-User` are allowed; `ClaudeBot`, `Applebot-Extended` and `meta-externalagent` are blocked; `User-agent: *` carries `Content-Signal: search=yes, ai-input=yes, ai-train=no` ([Content Signals](https://contentsignals.org)).

## Security

- Includes the 0.20.2 security fixes (password Worker path refusals, confined `seite skill remove`/`install`).
- `--yes` / `SEITE_YES` never add auto-approve flags to `seite agent` or `seite theme create`; `seite agent --once --auto-approve` is honored only from an interactive terminal outside an agent session. Both refuse to start a nested agent inside Claude Code, Codex, Cursor, Gemini CLI or OpenCode, pointing to `/seite theme …` instead.
- Generated permissions allow only `seite theme apply` and `seite theme list`: Claude `Bash(seite theme apply:*)`, Cursor `Shell(seite:<subcommand>*)` per subcommand instead of `Shell(seite)`, OpenCode `"seite theme apply*"`.
- `seite init`, `upgrade`, `hooks` and the dev server refuse to write or delete through a symlink in any project path component and check the resolved parent stays inside the project.
- A planted `.seite/dev.json` can't spoof the dev server: its URL is ignored (rebuilt from the port), the port must accept loopback connections and the pid be alive, symlinks are ignored, and new sites gitignore it.
