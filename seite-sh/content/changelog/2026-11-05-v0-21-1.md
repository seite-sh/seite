A security release. Upgrade with `seite self-update`; no `seite upgrade` step is needed.

## Security

- **Unsafe `slug:` values are refused.** Before, a content file with `slug: ../templates/base` made `seite build` write that page outside `dist/`, over a project file such as a template. Anyone who could add a content file to a site (a pull request, a contributed post, imported content) could overwrite project files. A `slug:` with a `..` or `.` segment, an empty segment, a backslash, `:` or a control character now fails the build, `seite check` and the check hooks with `frontmatter-slug-invalid` at its line, and the page is not written. Every other tool that computes a page URL (MCP, `seite new`, import, audit) uses the file name instead of such a slug. See [frontmatter-slug-invalid](/docs/errors#frontmatter-slug-invalid).
- **Templates cannot read environment variables.** Tera's built-in `get_env()` let a template or shortcode copy a variable from the build environment, such as a deploy token in CI, into published pages. Combined with the slug bug, a content file could plant such a template. `get_env()` now fails the render (`template-render`) in page templates and shortcodes. If your templates used it, move the value to `seite.toml` or a `data/` file.

Thanks to EQSTLab for reporting the issue privately.
