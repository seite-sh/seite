# seite Brand Voice & Messaging

## Brand Voice Pillars

### 1. Pragmatic
- **What it means**: We solve real problems with working code, not promises
- **How it sounds**: Direct, specific, grounded in actual developer experience
- **Example**: "Install in 10 seconds. Build your site in under 1 second. Deploy with one command."
- **Avoid**: Hype, vaporware promises, "revolutionary"/"game-changing" language

### 2. Builder-Focused
- **What it means**: We speak to people who ship things, not people who evaluate tools
- **How it sounds**: Action-oriented, assumes competence, shows rather than tells
- **Example**: "Your coding agent can handle your website. Give it the right structure and it will."
- **Avoid**: Talking down, over-explaining basics, marketing fluff

### 3. Honest & Opinionated
- **What it means**: We have clear opinions about how sites should be built and we say so
- **How it sounds**: Confident but not arrogant, acknowledges tradeoffs openly
- **Example**: "Started as an experiment. Built with Claude Code. Used on our own startup's site."
- **Avoid**: Corporate hedging, "best-in-class" claims, competitor bashing

## Tone Guidelines

### General Tone
Imagine you're a developer friend who built something useful and is showing it to another developer over coffee. You're excited about it because it actually works, not because you need to sell it.

### By Content Type

**Documentation**: Clear, task-focused, minimal preamble
- "Run `seite init mysite` to create a new project"
- "Add `--drafts` to include draft content in the build"

**Blog/Changelog**: Conversational, specific about what changed and why
- "v0.4.0 adds skill packs — optional Claude Code agent bundles"
- "Fixed: sidebar nav now scrolls to active item on page load"

**Homepage/Landing**: Punchy, benefit-led, shows don't tell
- "Ship a landing page, docs site, or blog in an afternoon. Not a sprint."
- "6 bundled themes. Or describe one and let AI build it."

## Messaging Framework

### Core Message: AI-Native, Not AI-Bolted
- **Concept**: seite doesn't add AI as a feature — AI understands seite from the ground up
- **Key Points**: Auto-generated CLAUDE.md, MCP server, agent context, skill packs
- **Usage**: When discussing what makes seite different from other SSGs

### Core Message: One Tool, Not Five
- **Concept**: Replace CMS + deploy pipeline + form provider + changelog tool + docs platform
- **Key Points**: Built-in collections, deploy targets, contact forms, dev server
- **Usage**: When discussing the problem seite solves

### Core Message: Ship Fast, Ship Right
- **Concept**: Speed doesn't mean cutting corners — SEO, accessibility, and performance are defaults
- **Key Points**: Sub-second builds, automatic SEO/GEO, triple output
- **Usage**: When discussing build quality and developer experience

## Writing Style

### Word Choice
- **Conversational**: Write how you'd speak to a colleague
- **Specific**: "Sub-second builds" not "fast performance"
- **Active verbs**: "Ship", "Build", "Deploy", "Create"
- **Avoid fluff**: Cut "very", "really", "actually", "simply" unless needed

**Say This** -> **Not That**
- site generator -> content management system
- build -> compile / transpile
- deploy -> publish / go live
- collection -> content type / taxonomy
- agent -> AI assistant / copilot
- skill pack -> plugin / extension

## Quality Checklist

- [ ] Would a developer read this without rolling their eyes?
- [ ] Does it include a concrete example or command?
- [ ] Is it shorter than it could be?
- [ ] Does it respect the reader's time?
- [ ] Does it lead with benefits, not features?
