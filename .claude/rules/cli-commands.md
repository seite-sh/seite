# CLI Commands

- clap 4.5 with derive macros
- Each subcommand: `src/cli/{name}.rs` with `{Command}Args` + `pub fn run(args) -> anyhow::Result<()>`
- Interactive prompts go through `src/cli/prompt.rs` (wraps `dialoguer`), never called directly — it degrades safely under `--yes`/`-y`/`SEITE_YES=1` or a non-TTY: defaults are used where one exists, otherwise the command errors naming the missing flag
- Global `--json` prints exactly one document on stdout (`{"ok","command","data","warnings"}` or `{"ok":false,"error":{"message","chain"}}`, plus `data` if the command set it before failing); set a command's payload with `output::json::set_data()`. Rejected for `serve`, `agent`, `mcp`, `completions`, `self-update`

## Subcommands
init, new, import, build, check, serve, deploy, agent, theme, hooks, mcp, workspace, upgrade, contact, cms, collection, access, skill, self-update, completions, perf, telemetry, context, docs, page, search, stats, templates, frontmatter, explain, og

## Agent-facing commands
`seite preview` (dev server status, = `seite_get_errors`) and `seite docs|page|search|stats|templates|frontmatter` give shell agents every MCP-only capability. Each is a thin adapter in `src/cli/{name}.rs`: `site_tools::load_site(site)` (at a workspace root without `--site`: "this is a workspace: pass --site <name>" + site list) builds an `mcp::ServerState` for the site root (`--site` in a workspace, else `find_project_root` from cwd), `site_tools::call_tool(state, "seite_xxx", args)` calls the handler from `mcp::tools::TOOLS` (tool errors become anyhow errors, `seite_xxx: ` prefix dropped), then human output via `output::human` and the tool's structured result via `json::set_data()`. Never reimplement tool logic in the CLI. `page`/`frontmatter` turn a path that exists relative to cwd into an absolute one. `frontmatter set` parses `key=value` values as YAML only for bool/number/null, flow `[..]`/`{..}` and quoted strings; anything else is a verbatim string. `seite context` (`src/cli/context.rs`) reports site/collections (counts from `seite_content_stats`)/theme/local docs (`.seite/docs/`, gitignored, written lazily by `harness::ensure_local_docs` from `context`/`docs` when missing or stamp `.seite/docs/.version` differs; stale pages pruned)/skill packs/agents+hooks/dev server (`.seite/dev.json` with a live pid) and `NAME: message` directives from the pure `compute_directives()` (`CONFIG_INVALID`, `UPGRADE_AVAILABLE`, `NO_STOP_HOOK`, `TIMEZONE_UNSET` (schedule on, no `[site] timezone`), `DEV_BUILD_FAILED`, `BROWSER_ERRORS` (from the running server's `/__seite/status`), `ADDON_SUGGESTION`) plus a `Next:` hint naming `seite check` and `seite audit`; it succeeds outside a project. `seite explain <code>` prints the `## <code>` section of the embedded `errors` doc (`docs::error_sections()`); `main.rs` appends "Run `seite explain <code>` for details" to human `seite check` output whenever it reported diagnostics.

## seite import
`src/cli/import/` (`seite import <wordpress|ghost|jekyll|hugo> <source>`): each source module only parses into `Item`s (Markdown body, mapped fields, old URLs, `keys`/`refs` for cross-links) + `Skipped` + `Warning`s; `mod.rs` picks collections (must exist; `--collection`/`--pages-collection`), drafts (`--drafts`, else skipped), slugs (`-2` vs other items and existing URLs), filenames, aliases (`clean_aliases`: differs from new URL, `.html` dropped), refs, images (`images.rs`: downloads only from the export's host or `--allow-host`, manual redirects, `image/*`, 20 MB/file, `--max-download-mb`; copies canonicalized inside the source), frontmatter (fixed key order, schema checked, written anyway), writes via `safe_fs` (`--force`, `--dry-run`), and `.seite/cache/import-report.md`. Unknown Hugo shortcodes become inline code (seite would parse `{{<`); literal `{{<` in HTML is escaped `{{\<`. Deterministic: sorted items, no timestamps/absolute paths in the report.

## seite audit
`src/cli/audit.rs` (thin) → `audit::run` (`src/audit/mod.rs`): `cli::check::scratch_build` (never `dist/`) or `--dist <dir>` (generated-file attribution, no `content` checks); `Site::load` scans every `.html` once (`audit::html::scan`, a forgiving tokenizer reusing `build::links` tag/attr parsing), `attach_items` maps pages to content items (source, word count, dates, lang). Checks in `seo.rs`/`geo.rs`/`a11y.rs`/`content.rs`/`perf.rs` push `Finding::new("<code>", page_url, message).at(loc)`; every code is a row of `audit::CODES` (category, severity, hint) and a `## <code>` in errors.md. `collapse()` merges shared (template/data) findings by code+file+line. Flags: `--category` (repeatable/comma), `--fail-on error|warning` (sets data, then errs), `--min-severity` (via `Report::limit`; summary unchanged), `--top N` (human only), `--dist` (collections from `url_prefix`, site description = missing description). Asset paths are confined to the output dir (`perf::confined_rel` + canonicalize). JSON: `{summary:{score,errors,warnings,notices,pages,by_category}, omitted, findings:[{code,severity,category,page_url,file,line,message,hint,docs_url}]}`. MCP `seite_audit` (`categories`, `top` = 50, `min_severity` = warning) returns the same.

## seite check
`src/cli/check.rs` runs config, frontmatter, shortcode, data-file, template, render, link, and asset validation via `check_site()` — the real build pipeline (`build::build_site`), but rendered into a `tempfile` scratch dir that's always discarded, so `dist/`/`dist-subdomains/` are never touched. Diagnostics come back as one sorted, deduplicated `Diagnostics` list (see `src/diagnostics.rs`); paths are relativized back to the site root (`relativize()` strips the scratch prefix from both `file` and any absolute paths quoted in the message). `--strict` also fails on warnings (e.g. `config-unknown-key`, `broken-link`); `--drafts` includes draft content. Exit 0 (no errors, or in `--strict` no diagnostics at all) / 1 otherwise; `--json` shape is `{"diagnostics": [...], "summary": {"errors", "warnings"}}` on success and `error.diagnostics` on failure. Output is compiler-style: `file:line:col: severity[code]: message` + an indented `hint:` line. In a workspace, `--site <name>` (or running at the workspace root, which has no `seite.toml`) goes through `check_workspace()`: each site via `check_site_with()` (workspace `base_url` override), files prefixed with the site path via `Diagnostic::under()`. Workspace `build` loads each site with `workspace::load_site_in_workspace_with_diagnostics()` (unknown-key warnings, prepended to that site's `BuildResult.diagnostics`) and, with `--strict`, builds every site then fails via `cli::build::strict_failure()` with workspace-relative link diagnostics. `--external` (standalone sites only) runs `check_site_full(.., Some(strict))`, which after the scratch build calls `build::external_links::run` on the scratch output (page→source map from `BuildResult.collections`, fallback templates/data/content) and adds `data.external` `{found, checked, cached, skipped, broken, unreachable}`; never in hooks. Check resolves links like the build (`--future` sets `config.build.future`), reports links to hidden pages as `link-to-scheduled` (`schedule::link_diagnostics`), renders scheduled pages in a second scratch build keeping only their diagnostics, and prints the `schedule::hidden_summary` info note. `--file <path>...` runs `check_files()` (also validates the file's collection schema, drafts included): config + per-file frontmatter/shortcodes (content), Tera syntax (templates), data-file syntax, no render; each skipped path (missing, outside the site, unhandled extension) is a `check-file-skipped` warning. `--hook <claude|codex|cursor|opencode|gemini|copilot>` runs it as a coding agent's hook (`src/cli/harness_hooks.rs`): reads hook JSON on stdin, prints that harness's protocol JSON only when there are errors (capped at 40 lines), honors loop guards, and always exits 0 (silent outside a site; internal failures only note on stderr; Cursor, natively or running Claude's hooks, always gets at least `{}`). `--post-edit` checks only the edited file(s) named in the hook input (`edited_paths()`: `tool_input.file_path`, Codex `apply_patch` headers, top-level `file_path`).

## Agent System
`seite agent [--with claude|codex|opencode|cursor|gemini|copilot] [--once] [prompt]` (default `SEITE_AGENT`, else claude) is a thin launcher: the prompt is passed as-is (no injected context, no `--allowedTools`/`--mcp-config`); the agent reads AGENTS.md and the `/seite` skill. Interactive by default (`claude "<prompt>"`, `gemini -i`, `opencode --prompt`), `--once` runs one-shot (`claude -p`, `codex exec --sandbox workspace-write`, `opencode run`, `cursor-agent -p`, `gemini -p`, `copilot -p`; interactive `copilot -i`, skill prompt "Use the /seite skill: …"); only `--auto-approve` (never `--yes`/`SEITE_YES`) adds the harness's auto-approve flag, and only from a TTY outside an agent session. `agent::refuse_nested()` makes `seite agent` and `seite theme create` (agent branch) fail inside an agent session, detected from `AGENT_SESSION_MARKERS` (CLAUDECODE, CODEX_THREAD_ID/CODEX_SANDBOX*, GEMINI_CLI/GEMINI_PROJECT_DIR, OPENCODE, CURSOR_AGENT/CURSOR_PROJECT_DIR, CLAUDE_PROJECT_DIR; sources commented there; Copilot documents none, so it isn't detected). Integration tests' `page_cmd()` strips these vars. Per-harness argv lives in the `Harness` enum in `src/cli/agent.rs` (`run_once` is reused by `seite theme create`, which runs `/seite theme <desc>` or points to `/impeccable` when installed).

## Dev Server
`seite serve` starts HTTP server + file watcher. Returns `ServerHandle`. Shows Vite-style local + network URLs. `--open` launches browser, `--build` builds first. Interactive REPL (new, agent, theme, build, status, stop) reads stdin unless `--no-repl` is passed; the prompt is only printed to a real TTY, and if stdin closes (e.g. `</dev/null`, a background job) the server keeps serving instead of exiting. A failed initial build no longer aborts serve: it is printed and recorded (overlay + `seite preview`).

`src/server/dev.rs` is the one implementation of every dev endpoint and of the injected script, shared by the single-site server (`server/mod.rs`) and the workspace server (`workspace/server.rs`; both call `dev::handle_request` first, then serve files). `DevState` holds the build version, last `BuildOutcome` (`{ok, at, duration_ms, errors, warnings, diagnostics, message}`; `PageError::Diagnostics` → its diagnostics relativized to the site, other errors → `message`; workspace: per-site outcomes merged, paths under the site path), a 50-entry `ErrorRing` of browser errors (identical repeats counted), a 20/s `RateLimiter`, the SSE senders, and a build lock (watcher, `seite_reload`). Watchers record every rebuild via `DevState::run_build`/`record_site_builds`; `seite serve` records the initial build. Endpoints: `GET /__livereload` (polling fallback), `GET /__seite/events` (SSE: `reload`, `build-ok`, `build-error` JSON; one thread per client writing raw HTTP through `Request::into_writer` because tiny_http's chunked encoder buffers 8 KB; max 32 clients → 503; heartbeat 15 s; a failed last build is sent on connect), `GET /__seite/status`, `POST /__seite/console` (8 KB body, message 2 KB, `sanitize()` strips ANSI/controls/bidi before `human::warning("browser: …")`), `POST /__seite/clear-browser-errors`, `POST /__seite/mcp`. Guards (pure fns, unit-tested): read/console endpoints need `host_is_trusted` (loopback name or IP literal + our port: rebinding needs a domain), console also same-origin + JSON content type; status/events also need `origin_matches_host` (HEAD on events: headers only); console needs a declared Content-Length ≤ 8 KB (none → 411) and, on a network bind, a loopback peer (`remote_addr`); MCP and clear (`local_client_guard`) need a loopback peer and Host, NO `Origin` at all (browsers send one on every POST, same-origin included) and JSON; MCP is 403 when bound to a non-loopback `--host`, 1 MB body, max 4 concurrent handlers (503), GET 405, notifications 202. Any request declaring a body > 1 MB gets 413 + `Connection: close` before anything reads it. Guards and caps run before any thread is spawned. Over HTTP MCP, `seite_build` calls `DevState::rebuild_now` (dev config, build lock, SSE), never a production build into `dist/`. Workspace: a whole-workspace initial failure (site `""`) is dropped once per-site outcomes arrive. No `Access-Control-Allow-*` header anywhere. The script (`LIVERELOAD_SCRIPT`, injected before the last `</body>` by `inject_livereload`) uses `textContent` only inside a shadow root, respects reduced motion, falls back to polling, and never re-reports its own forwarding failures. `src/server/remote.rs` is the client side (`seite preview`, `seite context`, stdio runtime tools): finds the server via `context::running_dev_server` (site root, then workspace root), talks to `http://127.0.0.1:<port>` with no proxy, and refuses a server whose status `root` is another site.

`seite preview [--json] [--clear-browser-errors]` (`src/cli/preview.rs`) prints the status (URL, last build as compiler-style diagnostics, browser errors); no server → exit 1 with `data: {running: false}`; last build failed → exit 1 with the status as data; strings printed are `sanitize()`d; `--clear-browser-errors` clears atomically (the endpoint returns what it removed). The server is found only on 127.0.0.1 (the URL is rebuilt from the port), and `remote::site_url_in` refuses a server whose status `root` is another site (preview, context, stdio tools). Browser errors always come with `BROWSER_ERRORS_NOTE` (untrusted page output) — `seite_get_errors` returns them as `untrusted_browser_errors`. `seite context` reads `/__seite/status` with a 300 ms timeout and adds `DEV_BUILD_FAILED` / `BROWSER_ERRORS` directives. After binding it writes `.seite/dev.json` `{pid, port, url, started_at}` (cwd, or the workspace root) via `safe_fs`, removed on stop/Ctrl-C/SIGTERM (`signal-hook` on unix); a live recorded server makes a second `seite serve` print its URL and exit 0 unless `--force-new`. `context::running_dev_server()` trusts only pid+port: pid alive (unix) AND loopback port accepting, URL rebuilt as `http://127.0.0.1:<port>`, symlinked files ignored (no git probe: git in an untrusted repo can run its config).

## Workspace System
Multi-site via `seite-workspace.toml`. `workspace::resolve_context()` returns `Standalone` or `Workspace`. `--site` flag filters. Unified serving routes `/<site-name>/...`.

GitHub Pages (git push), Cloudflare (wrangler), Netlify. `auto_commit = true` by default. Non-main branches auto-use preview. `--dry-run` for preview.

## Skill Pack System
`seite skill install|list|remove|update [--agents]`. Known: `seomachine` (11 agents, 24 commands, 25 skills; pin in `src/cli/seomachine.pin` = repo, 40-char commit, and SHA-256 per file, refreshed only by `scripts/refresh-seomachine-pin.sh` at release time; `install_pack_with` fetches via an injected `Fetch`, verifies every hash in memory, aborts before writing anything on mismatch; skills go to each selected agent's `harness::PROVIDERS` skills dir (`portable_skill_md` strips non-name/description frontmatter outside Claude), agents/commands only for claude; `update` = reinstall at the binary's pin, agents from `--agents` > manifest > `.seite/config.json` > all) and `impeccable` (after an npm check + confirm, `npm install --prefix <tempdir> impeccable@IMPECCABLE_VERSION` runs from that temp dir — never the project, whose `.npmrc`/`node_modules` could swap it — then `<tempdir>/node_modules/.bin/impeccable install --providers=<agents> --scope=project -y` / `update --scope=project -y` runs in the site root; manifest entry `source: npm:impeccable`; remove deletes only skill dirs whose SKILL.md `name:` is impeccable). All skill deletes go through `safe_fs`. Manifest in `.claude/.seite-skill-packs.json` is repository-controlled, so untrusted: `remove_if_unmodified` deletes only regular files in `owned_paths(pack)` (every dest `plan_files` can produce for any agent), never directories/symlinks, never legacy `context/` files (`commit`, `date`, `agents`, `kept` = edited files left behind by update, per-file `hashes`; old entries without them still load; `remove`/update keep files whose hash no longer matches, and untracked existing files are never overwritten). SEOMachine AGENTS.md section managed by HTML comment markers.

## Coding-Agent Harness Files
`seite init --agents [--mcp]` / `seite upgrade --agents [--mcp]` (in a workspace root or with `--site`, upgrade plans every site and confirms once) (claude, codex, opencode, cursor, gemini, copilot; default all, stored in `.seite/config.json`). All rules, skills, hooks, and (opt-in) MCP entries come from `src/cli/harness.rs` + `harness_hooks.rs`; upgrade merges via `check_agent_harness()` in `src/cli/upgrade.rs`. `seite hooks on|off|status [--tier stop|post-edit|all]` (`src/cli/hooks.rs`) manages the check hooks. `.seite/config.json` `hooks_installed` records tiers: bare `<agent>` = turn-end (0.20's meaning), `<agent>:post-edit` = after-edit; upgrade adds only unrecorded tiers (0.20 bare records get post-edit only while their stop hook is present). `remove_hook_kinds` removes only exact seite-generated commands; OpenCode's plugin is deleted only when it equals a bundled version. Every harness/upgrade/hooks write and delete goes through `crate::safe_fs` (refuses symlinked components below the root, canonical parent must stay inside). Upgrade also prunes 0.20's legacy AGENTS.md sections (`src/scaffold/legacy/`, whitespace-normalized exact match) and shows one-time notices (`notices_shown`), never under `--check`. Permissions allow only `seite theme apply|list` (Claude/OpenCode/Cursor `Shell(seite:<sub>*)`); upgrade narrows exact 0.20 rules.

## Built-in Skills
One routed skill, `/seite` (SKILL.md + `reference/{check,new,preview,build,deploy,theme,brand,landing,collection,upgrade,hooks}.md`; OpenCode gets `.opencode/commands/seite.md`, Gemini `.gemini/commands/seite.toml`). Scaffolded by init into `.claude/skills/seite/` (Claude) and `.agents/skills/seite/` (Codex/Cursor/OpenCode/Gemini/Copilot), upgraded with version tracking (`# seite-skill-version: N`, references replaced with SKILL.md). Per-agent paths/formats come from `harness::PROVIDERS`.

`seite skill export <dir> [--format skills|claude-plugin|repo]` (hidden; `src/cli/skill_export.rs`, wired as `SkillCommand::Export` in `skill.rs`) renders the same skill for installs without `seite init`: `skills` → `<dir>/seite/` (portable frontmatter, for `npx skills add seite-sh/seite`), `claude-plugin` → a Claude Code plugin (`.claude-plugin/plugin.json`, `skills/seite/` with `argument-hint`, `hooks/hooks.json` = the Claude hooks of `seite init`; no MCP), `repo` → this repository's checked-in `skills/`, `plugins/seite/`, `.claude-plugin/marketplace.json`. Writes only changed files and prunes stale files under the paths it owns (`owned_paths`), through `safe_fs`, and only inside a skill dir whose `SKILL.md` carries `# seite-skill-version` (else it refuses). The plugin's hooks run `seite check --hook claude --plugin` (hidden flag): turn-end only after a post-edit marker (`.seite/cache/plugin-edited`), standing down when `.claude/settings.json`/`.claude/settings.local.json` has seite's hook. `tests/integration/skill_export.rs` fails when the checked-in copy drifts; regenerate with `cargo run -- skill export . --format repo`.
